注文管理API / SREランブック RB-118

対象サービス注文管理API（order-api）
想定所要時間約15分
実施権限SRE当番エンジニア

前提条件

対象サービスは blue / green の2スロット構成で稼働しており、常に一方のみがロードバランサーの アクティブ経路に接続されている。デプロイは非アクティブ側のスロットに対して行い、 ヘルスチェック通過後にロードバランサーの向き先を切り替える。

現在のアクティブスロットは app-green です。今回のデプロイでは、 非アクティブ側のスロットに新バージョンを展開します。

本手順の実行前に、対象バージョンのイメージが registry に push 済みであることを確認すること。

手順

  1. 変更対象のリリースタグを確認し、下記スクリプトの環境変数を設定する。
  2. 非アクティブスロットに対してデプロイスクリプトを実行する。
  3. ヘルスチェックエンドポイントが 200 を返すことを確認する。
  4. 問題がなければロードバランサーの向き先を新スロットに切り替える。
  5. 切替後、旧スロットを一定時間待機状態で保持してからスケールインする。

実行スクリプト

#!/bin/bash
set -euo pipefail

SLOT="green"
RELEASE_TAG="v1.8.0"
HEALTHCHECK_URL="http://green.internal:8080/healthz"

echo "Deploying ${SLOT} slot (${RELEASE_TAG})"

docker pull registry.example.com/app:${RELEASE_TAG}
docker stop app-${SLOT} || true

docker run -d \
  --name app-${SLOT} \
  --env SLOT=${SLOT} \
  --env RELEASE_TAG=${RELEASE_TAG} \
  --restart unless-stopped \
  -p 8080:8080 \
  registry.example.com/app:${RELEASE_TAG}

sleep 5
curl -fsS ${HEALTHCHECK_URL} > /dev/null

echo "Deployment complete"

実行後の確認

  • ヘルスチェックのレスポンスタイムが平常時と同水準であること
  • エラーレートのダッシュボードに異常なスパイクがないこと
  • 旧スロットのコンテナが意図通り停止していること
